# GPU-kernel domain module

Load only for explanations or reports whose central subject is a GPU kernel or
GPU execution pipeline. This module adds domain questions; it does not replace
the primary type or mechanism-analysis lens.

Trace the mapping from logical work to grid, block, warp, and thread; tensor or
array shapes; launch configuration; memory spaces and access pattern; barriers
or synchronization; control-flow divergence; and the produced output. For
performance claims, state hardware, compiler/toolchain, input shape, precision,
baseline, warm-up/repetition policy, and metric definition when disclosed.

Separate functional correctness evidence from throughput, latency, occupancy,
bandwidth, or resource-use evidence. Treat optimization explanations as
inference unless the source measures or directly states the causal mechanism.
